# Mohammad Alif Hasnain

Senior Mobile App Developer, Dhaka, Bangladesh. 5.5+ years shipping Android and Flutter to production, currently at SSL Wireless.

## How I work

  • I focus on building clear architecture before adding features. Good foundations make products easier to maintain and evolve.
  • I prefer a single source of truth for each screen, keeping state predictable and reducing unnecessary complexity.
  • I value consistency over cleverness. Code should be easy for the next engineer to understand, extend, and debug.
  • I optimize for long-term maintainability, making thoughtful trade-offs instead of chasing short-term solutions.

## Choosing the platform

Flutter is not a cheaper Android. Native is not a safer default. It is a product decision.

Native · Kotlin + Compose
When the app lives close to the OS: background work, widgets, Wear and Auto surfaces, tight camera or sensor paths — or when the domain belongs in a shared KMP module.

Flutter
A great fit for teams building for both Android and iOS, products with highly customized UI, or projects where sharing a single codebase provides clear value.

> What I refuse: rewriting a working native app so it looks modern on an architecture slide.

## Built for a hostile client

A payment SDK that runs inside merchant apps I do not control, on devices I cannot trust. Transport, on-device storage and the shipped build artifact are each treated as an attack surface rather than an implementation detail.

The governing constraint
A deliberately narrow public façade over self-contained flows; every session timeboxed to a server-issued token; no payment data left on the device once a flow closes.

PIN entry, OTP and liveness checks stay inside the SDK, so an integrator never handles them.
